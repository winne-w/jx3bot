## Purpose

为 JJC 数据中心提供已知角色的最新 3v3 战绩摘要，通过独立任务、角色冷却、来源限频及有限历史页调用控制刷新规模；用户先读本地结果，刷新失败仍保留旧数据，完整历史分页和统计水位保持独立。

## ADDED Requirements

### Requirement: 本地读取不触发官方调用
系统 MUST 让列表与刷新状态 GET 只读取本地数据，不创建任务、不等待或触发官方调用。功能关闭时 MUST 仍允许读取已有摘要和完整历史。

#### Scenario: 数据过期但用户读取列表
- **WHEN** 用户 GET 已知角色的对局列表且成功检查时间已经过期
- **THEN** 返回已有数据和刷新状态，不创建任务或访问官方

#### Scenario: 功能关闭后读取已有摘要
- **WHEN** 本地已有未过期摘要且最新刷新功能关闭
- **THEN** 仍返回摘要和历史列表，刷新状态为 disabled

### Requirement: 公开刷新只接受可靠本地身份
系统 MUST 通过 POST 为本地已知身份提交任务；缺少有效 SK01 时，只能在本地身份具备可靠查询字段时进行一次必要身份补全并核对结果。未知或不一致身份 MUST 返回 identity_unavailable，不能扩展为任意角色官方搜索。

#### Scenario: 未知角色提交刷新
- **WHEN** 用户提交本地不存在的服务器和角色名
- **THEN** 返回 identity_unavailable，不为该角色请求官方历史或身份补全

#### Scenario: 身份补全返回其他角色
- **WHEN** 补全结果的角色 ID、区服或服务器与本地身份不一致
- **THEN** 拒绝该身份结果，不继续历史请求

### Requirement: 最新摘要限制业务调用并先发布首屏
系统 MUST 每次任务最多调用两页历史，每页最多请求 20 条，并在必要时最多调用一次身份补全。该限制描述业务逻辑调用，不规定现有直连 HTTP 内部重试的网络尝试总数。系统 MUST 仅接纳有效本赛季 3v3 记录，第一页结果先发布，不等待第二页或详情。

#### Scenario: 最新对局详情尚未保存
- **WHEN** 第一页返回有效本赛季 3v3 基础战绩而完整详情尚不可用
- **THEN** 该页摘要先可被列表 GET 读取，不因第二页或详情未完成而延迟

#### Scenario: 两页未覆盖全部新增记录
- **WHEN** 第二页仍满页且尚未遇到已知摘要边界
- **THEN** 标识 coverage_limited，不请求第三页，不推进完整历史水位

### Requirement: 摘要合并保留且上限四十条
系统 MUST 将有效新摘要与已有未过期摘要按对局 ID 合并去重，按时间倒序最多展示 40 条。成功空结果 MUST 保留旧摘要并更新成功检查时间；失败 MUST 保留已发布摘要和上一成功检查时间。

#### Scenario: 成功但没有新对局
- **WHEN** 官方有效结果为空或仅包含已知记录
- **THEN** 保留先前摘要，更新成功检查时间并进入冷却

#### Scenario: 第一页发布后第二页失败
- **WHEN** 第一页已发布且第二页请求失败
- **THEN** 第一页和合并后的旧摘要仍可读，任务标识失败且不更新上一成功检查时间

#### Scenario: 合并后超过四十条
- **WHEN** 新旧有效摘要去重后的记录超过 40 条
- **THEN** 仅返回最新 40 条，保留覆盖有限状态和独立历史分页

### Requirement: 同角色共享任务及服务端冷却
系统 MUST 跨进程按规范身份、赛季和比赛类型合并刷新任务，手动和自动提交均遵守服务端冷却；失败 MUST 进入有上限的角色退避。

#### Scenario: 并发访问和手动刷新
- **WHEN** 多个进程同时接收同角色刷新，随后用户在冷却期再次点击
- **THEN** 最多存在一个有效任务，重复提交返回已有状态，不新增执行任务

### Requirement: 任务总容量有界并隔离过期执行者
系统 MUST 原子限制排队与运行任务的总容量，限定有效期，并允许过期槽位供后续提交复用。旧代执行者 MUST 不能覆盖当前摘要指针、任务状态或释放新代任务槽位。

#### Scenario: 并发争抢最后的可用槽位
- **WHEN** 多个不同角色请求同时争抢剩余任务槽位
- **THEN** 总占用不超过配置容量，未取得槽位的请求返回 queue_full

#### Scenario: 旧执行者在新任务开始后恢复
- **WHEN** 旧任务过期后同角色提交新一代任务，旧网络请求随后返回
- **THEN** 旧执行者不能改变新任务状态、可见摘要或槽位占用

### Requirement: 来源限频只信任明确配置的代理
系统 MUST 对公开刷新 POST 按来源实施滚动 60 秒最多 6 次限制，以带密钥散列保存来源，并仅通过明确可信代理解析转发链。超限 MUST 返回 HTTP 429、rate_limited 和 Retry-After。

#### Scenario: 非可信客户端伪造来源头
- **WHEN** 同一非可信连接来源通过修改 X-Forwarded-For 重复提交
- **THEN** 请求仍计入同一来源窗口，不能借任意转发头绕过限制

#### Scenario: 来源窗口已满
- **WHEN** 同一来源在滚动 60 秒内已提交 6 次又再次提交
- **THEN** 拒绝本次提交，返回 HTTP 429 和重试提示，不新增任务

### Requirement: 新功能默认关闭并隔离初始化失败
系统 MUST 默认关闭最新刷新，启用时检查必要凭据、来源密钥和 worker 可用性。新 worker 初始化或存储故障 MUST 仅使新功能降级并记录异常，不阻断 bot 启动及既有历史功能；公开响应不能暴露凭据或上游原始敏感错误。

#### Scenario: 启用时没有在线 worker
- **WHEN** 用户提交刷新而没有有效在线 worker
- **THEN** 返回 worker_unavailable，不接受无法执行的新任务

#### Scenario: worker 初始化存储异常
- **WHEN** bot 启动期间最新刷新初始化遇到 Mongo 或配置异常
- **THEN** 记录可诊断异常并停止新 worker 启动，bot 和既有历史功能继续启动

#### Scenario: 官方调用失败
- **WHEN** 当前刷新任务收到无效响应、鉴权错误、限流或其他上游失败
- **THEN** 当前任务进入失败退避并保留本地数据，公开响应不含原始敏感错误；不声称暂停全部直连调用

### Requirement: 前端兼容历史分页并有界轮询
系统 MUST 单独展示近期摘要和已同步历史，保留历史分页总数、已加载页和统计口径；摘要不能写入完整统计事实或推进历史水位。刷新期间 MUST 保留旧列表，显示成功检查时间和状态；轮询仅 GET 本地数据，每次最多 10 次，角色切换后丢弃旧响应。

#### Scenario: 刷新过程中切换角色
- **WHEN** 用户从角色 A 切换到 B 后 A 的请求返回
- **THEN** 停止 A 的轮询，不将 A 的结果写入 B 的界面

#### Scenario: 已加载历史后后台轮询
- **WHEN** 用户已加载多页历史，后台轮询取得新摘要
- **THEN** 更新摘要区，保留已加载历史页和原分页总数

#### Scenario: 十次轮询后任务仍未结束
- **WHEN** 已完成 10 次本地轮询且状态仍为 queued 或 running
- **THEN** 停止自动轮询，保留列表并提示稍后查看
