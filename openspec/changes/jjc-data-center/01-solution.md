# JJC 数据中心统一入口方案

## 总体方案

采用统一站点壳层、页面独立实现的方案。新增 `public/index.html` 作为入口，直接复用或承载 `jjc-ranking-stats.html` 的排名统计首页内容；三个页面仍是独立 HTML 文档，通过统一导航链接互相跳转。

## 信息架构

站点名称为“JJC 数据中心”，导航包含“心法排名”“对局查询”“心法对阵”三个入口，分别对应 `index.html`（首页）、`jjc-synced-matches.html`、`jjc-matchups.html`。为兼容直接访问 `jjc-ranking-stats.html`，该页面也保留并显示相同导航，首页链接统一指向 `index.html`。

## 页面壳层

三个页面增加一致的站点头部：品牌名称、简短说明和主导航。当前页面使用 `aria-current="page"` 与视觉高亮表示。桌面端使用水平导航；移动端允许横向滚动，保证导航项可访问且不压缩主要内容。站点壳层样式使用页面现有的深色数据分析视觉，统一间距、边框、圆角、状态色和最大内容宽度。

## 首页策略

优先避免复制大段排名页面脚本。将排名页面的文档入口调整为 `index.html` 的实际首页内容，并保留 `jjc-ranking-stats.html` 作为兼容入口；如果现有脚本依赖固定路径，应仅做相对路径和导航层面的兼容处理，不改变 API 调用和数据渲染逻辑。

## 链接与状态

导航使用普通相对链接，支持无脚本访问和浏览器前进后退。当前页面由页面标记或轻量脚本设置激活项，不引入路由器。链接失败、接口失败和空数据仍由各页面现有状态处理。

## 验证

验证入口和三个页面之间的链接、当前项高亮、页面标题与返回首页行为；在桌面和移动视口检查布局；运行现有前端静态契约测试，并对三个页面执行浏览器冒烟，确认原有查询、弹窗、分页、导出和详情交互没有回归。

## 风险与回滚

主要风险是复制或移动排名页面时遗漏脚本依赖，以及统一头部样式覆盖现有页面局部样式。实现时尽量抽取小范围壳层样式并保留原有 DOM 与脚本。若出现回归，可回滚新增入口和导航改动，三个原始页面仍可独立访问。
