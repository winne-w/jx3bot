# 开发方案

## 数据流与接口

QQ 消息 -> config.REGEX_PATTERNS 命令匹配 -> handler 参数提取和校验 -> query_jjc_ranking(tag: Optional[int] = None) -> 现有 JjcApiClient.get_arena_ranking(tag) -> 原有心法统计、存档及图片生成。

支持 `竞技排名 tag=40`、`竞技排名统计 tag=40 缓存心法`、`竞排名 拆分 tag=40 橙武占比 debug`。tag 参数与原有选项顺序无关；非法 tag 也应进入 handler 得到明确用法提示，同时维持拒绝无关命令选项的行为。

## 查询和缓存

未指定 tag：保留默认缓存读写及时间标签接口 data.defaultWeek 选择。指定 tag：不读写默认排行榜缓存，不调用时间标签接口，不执行原时间标签后的等待，直接使用输入 tag 请求排行榜。service 也校验 tag 是正整数（排除 bool）。手动请求失败直接返回已有错误结构，不重试为默认周。

返回 defaultWeek 等于实际请求 tag，cache_time 是本次查询时间，继续传给既有周次计算、统计存档与 renderer。手动查询的统计存档保留；仅绕过原始排行榜共享缓存。

## 取舍与边界

采用绕过默认缓存而非新增按 tag 缓存，避免污染定时任务和默认命令的数据且无需数据库迁移。历史 tag 的年份/赛季与心法展示继续遵循现有逻辑，不新增历史心法保证。

## 异常、日志与回滚

参数错误提示正整数及示例；排行榜错误、业务错误码、异常沿用 service 错误返回。日志记录手动 tag。回滚本需求提交即可恢复原命令与查询签名，无数据迁移。
