## Purpose

提供可按时间、双方任意心法组合和双方队伍平均游戏分区间查询的 JJC 3v3 对阵统计，并分页浏览唯一对局、下钻现有完整详情，以支持配置胜率与逐场奇穴研究。

## ADDED Requirements

### Requirement: 查询双方任意心法组合
系统 SHALL 允许配置 A 与配置 B 分别选择 0～3 个有效心法，并将非空配置按无序多重集合的“包含”语义匹配到一支三人队伍。

#### Scenario: 单心法对阵单心法
- **WHEN** 用户查询配置 A 为奶秀、配置 B 为明教
- **THEN** 系统返回一边包含奶秀且另一边包含明教的对局，不限制其余四个心法

#### Scenario: 混合数量的组合对阵
- **WHEN** 用户查询配置 A 为策藏、配置 B 为气明歌
- **THEN** 系统匹配一边同时包含策藏且另一边同时包含气纯、明教、长歌的对局

#### Scenario: 队内选择顺序不影响结果
- **WHEN** 用户使用相同心法但改变同一配置内的选择顺序
- **THEN** 系统返回相同的唯一对局集合和统计值

#### Scenario: 重复心法按数量匹配
- **WHEN** 一个配置包含重复的同一心法
- **THEN** 系统仅匹配对应队伍中该心法出现次数不少于查询次数的对局

#### Scenario: 单边配置为空
- **WHEN** 配置 A 或配置 B 为空而另一边非空
- **THEN** 系统将空配置解释为任意队伍，并统计非空配置对阵任意另一队的数据

#### Scenario: 双方配置为空
- **WHEN** 配置 A 与配置 B 都为空
- **THEN** 系统返回时间与分数条件内的全部可查询对局，并将胜场和胜率字段返回为 null，避免建立任意方向

#### Scenario: 非法配置参数
- **WHEN** 任一配置包含超过三个心法或包含未知心法 ID
- **THEN** 系统返回统一错误响应且不执行统计查询

### Requirement: 按双方队伍平均游戏分筛选
系统 SHALL 分别以每支队伍三名玩家的游戏分之和除以三作为队伍平均游戏分，并且仅在双方三名玩家分数都完整、双方平均分都落入左闭右开区间时纳入胜率与分页结果。

#### Scenario: 双方平均分命中区间
- **WHEN** 两支队伍各自三人平均游戏分都满足 `score_min <= score_avg < score_max`
- **THEN** 系统将该对局纳入有效对局统计和分页结果

#### Scenario: 仅一方平均分命中区间
- **WHEN** 只有一支队伍的平均游戏分落入所选区间
- **THEN** 系统不将该对局纳入有效对局统计或分页结果

#### Scenario: 玩家游戏分缺失
- **WHEN** 匹配时间和配置条件的对局中至少一支队伍有玩家游戏分缺失
- **THEN** 系统不将该对局纳入胜率和分页结果，并将其计入缺失分数对局数

#### Scenario: 平均分精确边界
- **WHEN** 队伍平均游戏分恰好等于下限或上限
- **THEN** 系统包含等于下限的对局并排除等于上限的对局，且判断不受页面显示舍入影响

#### Scenario: 非法分数区间
- **WHEN** 分数下限小于零或分数下限不小于分数上限
- **THEN** 系统返回统一错误响应且不执行统计查询

### Requirement: 按对局时间查询
系统 SHALL 使用对局实际发生时间作为时间筛选依据，支持最近 1、3、7、14、30 天和最长 90 天的自定义左闭右开时间范围，默认查询最近 7 天。

#### Scenario: 使用快捷时间范围
- **WHEN** 用户选择最近 7 天
- **THEN** 系统仅统计对局发生时间位于最近 7 天范围内的对局

#### Scenario: 使用自定义时间范围
- **WHEN** 用户提交合法且不超过 90 天的开始与结束时间
- **THEN** 系统统计满足 `start_time <= match_time < end_time` 的对局

#### Scenario: 不使用缓存时间筛选
- **WHEN** 对局发生时间位于查询范围外但同步时间或缓存时间位于范围内
- **THEN** 系统不纳入该对局

#### Scenario: 非法时间范围
- **WHEN** 开始时间不早于结束时间或自定义范围超过 90 天
- **THEN** 系统返回统一错误响应且不执行统计查询

### Requirement: 返回无结论的原始对阵统计
系统 SHALL 返回唯一有效对局数、方向样本数、双方胜场与胜率、双向命中数和缺失分数对局数，但 MUST NOT 推断或返回优势方结论。

#### Scenario: 单方向命中
- **WHEN** 一场对局仅能将配置 A 匹配到一队并将配置 B 匹配到另一队
- **THEN** 系统为该场生成一个方向样本，并按实际胜方累计配置 A 或配置 B 的胜场

#### Scenario: 双方向命中
- **WHEN** 一场对局的双方队伍都同时满足配置 A 与配置 B
- **THEN** 系统将该场计为一个唯一对局、两个方向样本、配置 A 一胜一负、配置 B 一胜一负，并将双向命中数增加一

#### Scenario: 交换双方配置
- **WHEN** 用户交换配置 A 与配置 B 后以相同时间和分数条件重新查询
- **THEN** 唯一对局数保持不变，双方胜场和胜率互换

#### Scenario: 返回客观数据
- **WHEN** 查询成功且存在有效样本
- **THEN** 响应只包含统计值和分页数据，不包含优势、劣势、均势或样本充分性结论

#### Scenario: 双方为空时浏览全部对局
- **WHEN** 配置 A 与配置 B 都为空
- **THEN** 系统返回唯一对局数、缺失分数对局数和分页数据，并将方向样本数设为 0、双方胜场及胜率设为 null

### Requirement: 分页浏览唯一对局并查看详情
系统 SHALL 按对局发生时间和对局 ID 倒序稳定分页返回唯一对局摘要，并允许用户通过现有对局详情能力查看六名玩家、装备和奇穴。

#### Scenario: 返回对局摘要
- **WHEN** 用户查询到有效对局
- **THEN** 每条摘要包含对局 ID、时间、地图、时长、双方三个玩家的心法和游戏分、双方平均分、胜负及实际匹配方向

#### Scenario: 双向命中详情去重
- **WHEN** 一场对局产生两个方向样本
- **THEN** 该对局在分页列表和分页总数中只出现一次

#### Scenario: 稳定分页
- **WHEN** 多场对局发生时间相同或用户切换页码
- **THEN** 系统以 `match_time DESC, match_id DESC` 返回稳定且不重复的分页结果

#### Scenario: 查看奇穴
- **WHEN** 用户点击分页列表中的一场对局
- **THEN** 页面使用该场 `match_id` 调用现有对局详情接口并展示包括奇穴在内的完整详情

#### Scenario: 空结果
- **WHEN** 时间、配置和分数条件内没有有效对局
- **THEN** 系统返回成功的空分页，并区分无匹配对局与存在匹配但分数不完整的情况

### Requirement: 提供独立的组合对阵统计页面
系统 SHALL 提供独立页面用于编辑组合查询条件、查看统计摘要和分页对局，并允许通过 URL 恢复和分享查询状态。

#### Scenario: 默认打开页面
- **WHEN** 用户首次打开页面且 URL 没有查询条件
- **THEN** 页面默认选择最近 7 天、空的双方配置和空的分数区间，并在用户填写合法分数区间前禁用查询

#### Scenario: 选择双方配置
- **WHEN** 用户为任一边添加或移除 0～3 个心法
- **THEN** 页面以标签展示选择结果并按所选多重集合提交查询

#### Scenario: 交换双方
- **WHEN** 用户点击交换双方
- **THEN** 页面交换配置 A 与配置 B，并在重新查询后交换对应胜场和胜率展示而不改变唯一对局集合

#### Scenario: URL 恢复查询
- **WHEN** 用户刷新或打开包含合法查询参数的页面 URL
- **THEN** 页面恢复时间、分数、双方配置、页码和每页数量并可重放相同查询

#### Scenario: 分页大小限制
- **WHEN** 用户选择分页大小
- **THEN** 页面允许每页 20、50 或 100 场，服务端拒绝超过 100 的分页大小

### Requirement: 对局级统计数据可重建且最终一致
系统 SHALL 从完整对局详情派生轻量对局统计事实，新对局写入后刷新该事实，并提供安全、幂等的历史回填和核验能力。

#### Scenario: 新对局投影成功
- **WHEN** 一场可用 3v3 对局详情保存成功
- **THEN** 系统按对局 ID 创建或覆盖对应的对局统计事实

#### Scenario: 重复投影同一对局
- **WHEN** 同一对局详情被重复保存或重复回填
- **THEN** 系统只保留一条最新版本的对局统计事实

#### Scenario: 投影失败
- **WHEN** 完整对局详情保存成功但统计事实写入失败
- **THEN** 系统保留完整详情、记录可定位的失败日志，并允许后续回填修复

#### Scenario: 默认运行历史回填
- **WHEN** 运维人员未显式指定写入确认参数而运行历史回填
- **THEN** 工具只读取和输出预计新增、更新、跳过与异常数量，不修改数据库

#### Scenario: 显式执行历史回填
- **WHEN** 运维人员在核对 dry-run 后显式确认写入
- **THEN** 工具分批幂等写入事实记录，并可在完成后核验缺失、版本错误和构建失败数量
