# 排名统计重新同步及队首优先方案

状态：用户已确认业务方案；实现细节与 TDD 顺序见 tasks.md。本 change 已发布验收，见 deployment.md。

## 用例与状态转换

触发为一次实际的排名统计运行，包括复用榜单缓存后重新计算；仅读已保存快照不触发。对该轮进入统计范围的有效身份去重，不以心法识别成功为前置条件。沿用已有统计范围，不扩展到统计范围之外的全部账号。

| 原状态 | 排名新请求行为 |
|---|---|
| 无任务 / pending | 建立或更新单条任务，立即 queued，加入队首段 |
| cooldown / exhausted | 忽略 next_sync_after，立即 queued，加入队首段 |
| failed | 忽略本次角色失败退避，立即 queued；保留失败审计，不伪造成功 |
| queued | 更新为最新排名批次并移动至队首段，不重复创建任务 |
| syncing | 原子记录待重排的最新请求，保留当前租约；释放或租约恢复时补排一次 |
| disabled | 跳过并记录原因 |

## 请求身份与幂等

统计 service 在每次运行开始时生成独立 run_id，贯穿即时入队及保存快照后的补充入口，不复用 cache_time 作为运行唯一标识。单轮同角色重复分组只更新一次，已有当前请求不得因保存快照再次移动或再次同步。新一轮请求可覆盖旧的尚未执行请求，多次请求合并成一条最新任务。

即时入口调整为按统计范围入队，包含心法未知且具有有效身份的成员，保存入口用于补齐。本轮实际请求参数包含 run_id、批次排序锚点、最近 14 天窗口和赛季信息。并发旧轮次的延迟保存不能把较新轮次覆盖回旧批次。

## 队首顺序

增加独立于既有数值 priority 的排名队首元数据，避免通过不断增加 priority 或把 queued_at 改成虚假的历史时间实现插队。当前未消费的最新排名批次位于所有普通 queued 任务之前，包括人工设置的高数值 priority；较旧排名批次随后，普通任务继续按既有 priority 降序、queued_at 升序处理。同一批次按原始排名稳定排序，最后以身份稳定键打破并列。

worker 领取、get_queue_position 和队列列表 queued 分组必须共用同一排序语义，并更新 identity/legacy 队列复合索引。历史记录缺少新字段时作为普通任务读取。成功消费后清除本次队首标记，保留现有成功后冷却与 priority 归零语义；普通失败重试恢复原有退避，不因已消费的排名标记永久占据队首。后续新的排名请求可再次插队。

## syncing 并发及恢复

队列文档保存最新请求、当前 worker 已领取请求及必要参数。排名请求不能把 syncing 直接改成 queued，也不能覆盖当前轮正在使用的窗口、租约或游标。worker 在有效租约下原子释放，若存在较领取时更新且未消费的请求，发布本轮水位/错误后转 queued 并采用最新请求参数，绕过本轮 cooldown/failed 退避；若无新请求，则使用原有成功/失败状态规则。

多次同步中请求只保留最新一个，释放时不能清除并发新写入请求；采用单文档原子条件更新或比较重试实现。旧租约 worker 不得发布结果或删除新请求。中断、过期租约恢复和进程重启同样保留最新未消费请求，并保证仅一个 worker 能领取。disabled 与全局鉴权暂停保持优先约束。

## 同步数据行为

重新入队继续使用 full 模式加本轮最近 14 天截止时间及当前赛季边界。worker 从 cursor=0 拉最新历史页，已有详情按原缓存和幂等保存逻辑复用，保留历史同步水位。排名心法后台刷新队列与本次对局历史同步队列仍是各自的任务。

## 验证范围

覆盖 identity 主路径和 legacy 兼容路径的全部状态、priority 为 0/1/100、尚未到期及已到期；验证最新排名批次先于普通高优先级及旧批次领取，列表与位置一致。同轮多分组及两入口幂等，复用 cache_time 的下一次统计仍重新入队；unknown 成员可入队，身份不足及 disabled 跳过。

并发测试覆盖请求与领取/成功释放/失败释放/中断/租约过期交错，旧请求延迟保存、旧租约迟到与重启恢复；验证 syncing 不被抢占，新请求最终只补排一次。用隔离 Mongo 验证真实原子更新和排序索引，不以生产库跑测试。最后回归 dispatcher、角色查询入队与统计保存失败隔离。

## 风险、上线与回滚

排名重新插队会增加刷新频率，并可能延迟普通角色处理，这是用户要求的优先策略；同轮去重、跨轮待处理请求合并及已有详情复用控制重复工作量。上线时需要 bot 和独立 worker 同版，避免旧 worker 按旧排序领取或在释放时丢失待重排请求。先停旧消费者，再发布同版并恢复；数据库字段向后兼容，但回滚前须把新增待处理请求转成普通 queued，保证请求不丢。字段、索引、TDD 命令及回滚步骤见 tasks.md 和数据库/运行手册；本次已于 2026-11-07 发布，详见 deployment.md。

## 已实现的最小数据契约

四个字段为 ranking_request_order（已接受最新请求标识，保留用于去重）、ranking_pending（同步中收到的新请求参数）、queue_front_order（待领取的排名批次）、queue_front_rank（原始排名）。无需额外的已领取 generation：只有状态 syncing 时到达的新请求才写 pending，领取前已经接受的请求就是当前轮；该判定和状态转换在同一文档原子完成。正常完成清除 front，pending 存在时一次原子释放并重排。

排序末尾用 identity_key 和 _id 稳定打破并列；新增 idx_status_ranking_front 到 identity/legacy 两个集合。请求的原子单调条件允许并发旧请求自动被新请求覆盖，release CAS 则比较最新请求标识，避免清掉并发写入的 pending。人工 priority 调升使用 $max 保留，pending 发布时比较并保留当前优先级。
