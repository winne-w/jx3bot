## Why

排名统计串行查询心法，每角色还包含随机等待与可能的回放/详情请求，已有角色被反复查询。本次按用户提出的“历史结果复用，上榜角色入队定时更新”解耦统计与刷新。

2026-11-06 修订：采纳三个子 agent 的[独立设计评估](design-assessment.md)，心法归入角色画像，刷新队列独立，缩减首版范围。本轮仅修订方案和 TDD 计划，不开始实现、建表或部署。

## What Changes

- 在 `role_identities.jjc_kungfu` 保存最近成功判定的 3v3 主打心法，附来源、独立验证时间、适用赛季/算法和发布版本。失败不清空成功结果，不推进身份更新时间。
- 新增 `jjc_kungfu_refresh_queue`：每角色一条当前 3v3 长期任务，仅存调度状态；pending/running 两种状态，一个 next_run_at 表达周期刷新与重试，角色级 generation 不因赛季切换归零。
- 当前排名批量读取角色心法并幂等登记榜单角色。缺失或过旧者记未知，保留排名与人数；前台不外呼、不等待后台补齐。
- 一个后台消费者复用既有异步 HTTP 能力，仅查询基础心法所需 indicator/history，复用原判定口径；不强制查询武器、队友、回放、详情。
- 采用有条件写角色结果后确认队列的至少一次处理，补全中断、写入结果未知、旧任务迟到与作用域切换的恢复规则；不使用多文档事务。
- 冻结统计实际采用的心法与时效，最小展示识别覆盖率/未知；辅助信息缺失不冒充已检查，历史快照不重算。
- 用独立开关先预热再切流，保留历史 tag、旧入口和旧快照兼容。

首版移除前台十人/30秒等待、全局 control 选主/双心跳、持久化全局请求间隔、差异化排名周期/防饥饿、旧数据 seed 平台和装备分母版本升级。保留任务租约、有限超时、退避、身份保护及真实 Mongo 竞争测试。

## Capabilities

### New Capabilities

- `jjc-kungfu-refresh`：角色主打心法属性、独立持久化队列、条件发布、失败恢复与单消费者运行。

### Modified Capabilities

- `jjc-ranking`：批量复用角色心法、缺失立即未知并登记、时效与覆盖率快照、新旧入口兼容。

## Impact

涉及角色身份仓储、独立队列仓储、排名服务、共享判定、薄异步推栏适配器、运行装配及 Mongo 索引；最小调整快照透传与展示。实施文件、TDD 顺序和验证见 [tasks.md](tasks.md)、[test-plan.md](test-plan.md)，数据库及发布协议见 [design.md](design.md)。

不新增 Redis/消息中间件，不修改完整历史同步水位，不重建身份，不批量伪造旧心法验证时间。单消费者是首版部署约束，不能宣称已有跨进程总限流或热备能力。时效参数与性能指标均为待验证初值。
