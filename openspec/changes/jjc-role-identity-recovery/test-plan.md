# TDD 测试与验证矩阵

状态：2026-10-20用户已批准并进入TDD实现及review闭环。tasks.md 为执行顺序和命令的唯一入口；本文规定测试断言与证据。发布/线上验收尚未执行，不以本地Green代替。

## Red / Green / Refactor 证据

每条需求对应测试ID、作者、文件/用例、Red命令与失败断言、Green命令与结果、实现commit、review发现及关闭记录。新函数不存在可先导入失败，随后须证明旧逻辑的行为断言失败，不能以环境错误替代Red。只在Green后局部重构，重构后全部相关组仍Green。

T1子agent写规则/仓储/隔离Mongo，T2写服务/CLI/排名；D1/D2负责最小实现，不共享写文件；独立reviewer只读。主agent复现Red、独立跑最终回归。批准tasks前不启动开发。

## 真环境而非Mock通过

隔离Mongo必须实际运行CAS竞争、两个进程、matched_count、missing/null、历史回退、归档及条件回滚；使用明确本地测试数据库，拒绝生产URI，清理只限该随机前缀数据库。skip不算通过，不在生产容器建测试库。Mock用于Red和分支，但不代替原子性证明。

本地.venv为3.13，生产为3.9。两者分开记录；真实3.9执行核心和服务测试、py_compile，当前环境没有3.9不意味着可免除门禁。依赖/镜像仅在隔离本地准备。

deadline和调用数量必须计入内部请求；5次为逻辑调用，不承诺底层重试后的总网络次数。线程取消后仍可能执行HTTP，应使用有限底层超时、迟到发布保护和断言，不将任务取消当网络已停止。

verify-applied仅直接只读数据库/必要上游，不用可能自愈或写缓存的公开API；公开API验收是另一类允许写入的操作。默认批次最多20，但100次包括apply和复验，不能据此承诺20个最坏情况全部完成。每次主动API预留剩余额度。

## 发布演练与线上验收

隔离演练allowlist制品hash、旧文件备份/恢复、配置不被覆盖。生产先预检/暂停旧写者/备份，再受控停止容器→替换→启动，检查文件hash和StartedAt而非只HTTP200。记录实际停机时间，出现冲突停止，不做全目录覆盖。

必须额外验证生产源码/依赖基线+实际overlay组合，而不只是本地commit。唯一允许配置变更是获批恢复开关，其他配置/凭据保持；第一次重启0，CLI试点通过后第二次重启1，再验证尚未修复代表角色的真实自动自愈。独立writer须实际重启重载或保持停止，不因文件变新就放行。

小耶猫先重新验证/备份/apply1，再核对原始indicator、Mongo身份、公开role-indicator/synced-role/list及真实桌面/手机页面；颜魉/盖伊伊与健康对照苍术补验。另一次受控重启后再读，避免临时内存修复假阳性。指标以执行时响应为准，不写死706场。每个声称恢复者须有身份回读与公开业务API成功；未公开核验列applied_unverified。

每批最多20，单并发/间隔/调用上限见design；串号/越权字段变化/回退任一出现即停止。原同步状态正确恢复后观察至少15分钟和一次真实相关写入，未覆盖自然周期如实列风险。无证据群体、真实无战绩与上游不可用不得算健康/已恢复，不能以抽样推算故障比例。
