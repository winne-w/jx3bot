# JJC 角色查询 ID 最小修复

## Why

2026-10-20 线上已同步对局页面的赛季战绩出现 indicator_3c_empty_fields。三个角色的历史快照、767 份现存详情、原始 replay 和成功 indicator 证明：转服后详情缺少 role_id，更新了服务器/名字却保留旧 ID，正确 indicator 又被“无对局时间只补空”拒绝。

本次样本中排行榜 gameRoleId、replay.role_id、indicator.role_info.role_id 是同一种查询 ID。用户已确认复用字段、最少改动，不新增查询身份对象。

## What Changes

- 现有仓储收口严格验证后的 ID 条件更新，复用字段、历史归档和刷新标记；不增加对象、字段、集合或常驻任务。
- 排名成功入口与页面失败的有界探测共用函数级规则；不能凭 source=indicator 授权覆盖。
- CAS 和历史组合保护同时防止并发及迟到历史资料回退。
- 一次性默认只读 CLI 支持盘点、核验、实时验证后更新、回读、继续和条件回滚。
- 增加唯一默认关闭的发布启用配置，保证CLI试点通过前公开/排名入口不自动恢复写入；不新增Mongo字段或对象。第一次重启关闭，试点后第二次重启启用，均纳入计划审批。
- TDD 包含子 agent 失败测试、子 agent 开发、独立 review、主 agent 验证与 commit、受控发布重启和线上验收。

## Scope And Non-Goals

覆盖所有本地身份的线索盘点与可验证角色恢复，不承诺缺候选、身份冲突、上游无战绩者自动恢复。不换主键、不合并角色、不改赛季/事实/历史对局/同步进度。不新增前端轮询、后台恢复 worker、恢复集合、强制覆盖或预算平台。本期暂不补 replay→detail.role_id。
