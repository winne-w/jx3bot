# 开发流程补充 review 与冒烟计划

## 背景

当前项目文档已规定二阶段开发流程、计划先行、按计划实现和验证，但没有把 code review 与冒烟测试纳入强制开发闭环。后续希望每次开发代码都完整走流程，并允许使用 Codex 子 agent 辅助 review 和测试。

## 目标

- 在项目级流程中明确完整开发闭环。
- 将冒烟测试纳入实现后的强制验证环节。
- 将 code review 纳入提交前强制环节，要求重复 review 和修复，直到没有必须处理的问题。
- 明确可调用 Codex 子 agent 进行 review、测试或冒烟辅助，但最终结果仍需主 agent 汇总判断。

## 非目标

- 不引入新的代码实现。
- 不改变现有分层架构、运行命令和业务验证清单。
- 不强制每次都必须使用子 agent；只规定可以使用，且高风险改动建议使用。

## 变更范围

- `PROJECT_CONTEXT.md`
  - 更新二阶段开发流程的阶段 2 规则。
  - 明确实现、冒烟、review、修复、再验证、提交、归档的顺序。
- `docs/design-docs/development-guide.md`
  - 更新提交前最小检查，加入 review 与冒烟要求。
- `docs/exec-plans/index.md`
  - 登记本计划。

## 验证方式

- 阅读修改后的 `PROJECT_CONTEXT.md`，确认流程顺序清晰且不与“计划先行”冲突。
- 阅读修改后的 `development-guide.md`，确认提交前检查包含冒烟和 review。
- 执行 `git diff --check` 检查文档格式。

## 风险与回滚

- 风险：流程描述过重，影响小改动效率。
- 缓解：保留二阶段框架，小改动仍可写最小计划；review 和冒烟按影响范围选择最小集合。
- 回滚：还原本计划涉及的文档修改即可。
