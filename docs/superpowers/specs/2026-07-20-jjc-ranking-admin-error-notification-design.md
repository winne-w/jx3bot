# 竞技排名定时任务管理员错误通知

## 目标

当竞技排名定时任务无法产出并推送统计时，向 `config.py` 中 `ADMIN_QQ` 列表的每位管理员发送 QQ 私聊，便于及时排障。

## 范围

改动仅限 `src/plugins/status_monitor/jobs.py` 中的 `push_daily_jjc_ranking`。以下失败都会触发通知：排行榜结果为空、排行榜接口返回业务错误或非零错误码、心法统计结果为空或业务错误、统计为空、渲染失败，以及任务执行期间抛出的未捕获异常。

没有可用 Bot、没有启用竞技排名推送的群组属于任务未执行的前置条件，不发送错误通知。

## 方案

在插件层增加一个仅负责管理员私聊的异步辅助函数。调用方传入当前 Bot 与已格式化的失败描述；函数读取 `cfg.ADMIN_QQ`，逐一调用 `send_private_msg`。某个管理员私聊失败时只记录包含管理员 QQ 与发送异常的 warning，仍继续通知其余管理员，且不覆盖原始统计错误。

任务每个失败返回点先构造包含“竞技排名定时任务统计失败”和具体阶段/错误详情的文本，写入现有日志后调用该辅助函数。顶层 `except` 使用异常文本作为详情。成功推送和各群发送失败的现有行为保持不变。

## 测试与验证

新增异步单元测试，采用现有 `tests/test_config_manager.py` 的动态模块加载与依赖 stub 方式隔离 NoneBot 插件启动依赖。测试先失败，再实现最小代码使其通过：

- 辅助函数向所有 `ADMIN_QQ` 发送同一错误文本；一个私聊失败后仍发送下一位。
- 参数化验证排行榜为空、业务错误、非零错误码、心法数据为空或业务错误、统计为空、渲染为空和顶层异常都会调用通知。
- 验证无可用 Bot、无开启推送的群组均不调用通知。

随后执行新增测试、现有 `tests.test_status_monitor_jobs_config` 与 `py_compile`；线上手工通过替换服务返回结果或临时触发异常，确认管理员收到私聊且群推送不受影响。

## 取舍

备选做法是仅在顶层异常时通知，或为每个失败点复制私聊代码。前者会遗漏当前以正常 `return` 结束的业务失败；后者容易让文案和容错行为漂移。因此采用单一辅助函数加明确失败阶段的方案。
